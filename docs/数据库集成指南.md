# 数据库集成指南

## 概述

本文档说明如何将数据库存储层集成到现有的 websocket.py 中，实现从文件存储到数据库存储的平滑迁移。

## 架构设计

### 存储层结构

```
nanobot/storage/
├── __init__.py           # 模块导出
├── base.py              # 抽象接口 BaseStorage
├── database_storage.py  # PostgreSQL 实现
├── file_storage.py      # 文件存储实现（兼容现有）
├── storage_wrapper.py   # 包装器，提供统一接口
└── factory.py           # 存储工厂，管理后端选择
```

### 集成方式

```python
# 在 websocket.py 中使用 StorageWrapper
from nanobot.storage import StorageWrapper, init_storage

class WebSocketChannel:
    def __init__(self, ...):
        # 初始化存储（默认使用文件存储）
        # 可通过配置切换到数据库存储
        init_storage(backend="file")  # 或 "database"
        self.storage = StorageWrapper()
```

## 迁移步骤

### 1. 配置数据库连接

在 `~/.nanobot/config.json` 中添加数据库配置：

```json
{
  "database": {
    "url": "postgresql+asyncpg://nanobot:nanobot@localhost:5432/nanobot",
    "echo": false,
    "pool_size": 5,
    "max_overflow": 10
  }
}
```

### 2. 初始化存储

在 websocket.py 初始化时：

```python
from nanobot.storage import init_storage
from nanobot.config.schema import DatabaseConfig

# 根据配置选择存储后端
if config.database:
    await init_storage("database", db_config=config.database)
else:
    await init_storage("file")
```

### 3. 替换文件操作

#### 用户操作

**之前（文件存储）：**
```python
def _handle_users_register(self, request):
    users = self._load_users()
    key = f"{role}:{user_id}"
    users[key] = {...}
    self._save_users(users)
```

**之后（数据库存储）：**
```python
async def _handle_users_register(self, request):
    user = await self.storage.create_user({
        "user_id": user_id,
        "role": role,
        "display_name": display_name,
        "password_hash": hashed_password,
        "password_salt": salt,
    })
```

#### 课程操作

**之前（文件存储）：**
```python
def _handle_courses_create(self, request):
    course_id = self._generate_id()
    index = self._load_courses_index()
    index[course_id] = {...}
    self._save_courses_index(index)
    self._save_course(course_id, course_data)
```

**之后（数据库存储）：**
```python
async def _handle_courses_create(self, request):
    course = await self.storage.create_course({
        "course_id": self.storage.generate_id(),
        "course_name": name,
        "subject": subject,
        "grade": grade,
        "teacher_id": teacher_id,
        "teacher_role": teacher_role,
        "teacher_name": teacher_name,
        "join_code": self.storage.generate_join_code(),
    })
```

### 4. 处理异步操作

由于数据库操作是异步的，需要将 handler 方法改为 async：

```python
async def _handle_users_register(self, request: WsRequest) -> Response:
    # ... 异步操作
    user = await self.storage.create_user(user_data)
    return _http_json_response({"ok": True, "user": user})
```

## 存储后端切换

### 文件存储（默认）

```python
await init_storage("file")
```

- 数据存储在 `~/.nanobot/` 目录
- 兼容现有数据
- 无需数据库服务

### 数据库存储

```python
await init_storage("database")
```

- 数据存储在 PostgreSQL
- 需要先运行 `scripts/setup_database.py` 创建表
- 支持并发访问和事务

## 数据迁移

### 从文件迁移到数据库

```bash
# 1. 确保数据库表已创建
python scripts/setup_database.py

# 2. 运行迁移脚本
python -m nanobot.cli migrate-db --source file --target database
```

### 从数据库导出到文件

```bash
python -m nanobot.cli migrate-db --source database --target file
```

## 注意事项

1. **异步操作**：数据库操作是异步的，需要使用 `async/await`
2. **事务管理**：数据库操作自动使用事务，出错时自动回滚
3. **连接池**：数据库使用连接池管理连接，无需手动关闭
4. **兼容性**：StorageWrapper 提供与现有代码兼容的接口
5. **渐进式迁移**：可以逐步迁移，不需要一次性替换所有代码
